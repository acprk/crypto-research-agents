# 密码学论文写作手册（中文摘要）

> 英文原文：`skills/paper-playbook/`（总览 `SKILL.md`，各节 `sections/NN_*.md`，玩具示例 `examples/`）。
> 相关技能：abstract-craft、technique-overview、related-work-writing、experiments-writing、
> venue-calibration、mock-review、rebuttal、anonymize-check、camera-ready、artifact-pack、polish-writing。
> 所有示例均为虚构的玩具论文（LUT 打包加速 PBS、玩具 SPN 的差分区分器、低通信 PSI），数字仅作示意。

## 五条总原则

1. **每个数字只有一个来源**：摘要、引言、正文、表格、附录中的同一个数来自 `EVIDENCE.md` 的同一行；数字由脚本生成或 grep 核对，不凭记忆重打。
2. **先写可证伪的主张，再尝试推翻**：每条贡献先写成 `CLAIMS.md` 的一行，交给 falsifier 与 reviewer-sim 攻击，之后再润色文字。
3. **形式固定、措辞重写**：模板是结构，不是可复制的句子。
4. **正文承重，附录只作补充**：审稿人没有义务读附录，正文的任何结论不能只靠附录支撑。
5. **定稿阶段只做必要且可验证的修改**：截止前 24 小时只改错误，不做风格改写。

## 全文骨架与页数（LNCS，按正文上限等比缩放；以当期 CFP 为准）

| 节 | 占比 | 职责 |
|---|---|---|
| 摘要 + 关键词 | 第 1 页 | 研究现状 → 我们的技术 → 结果与制品 |
| 1 引言 | ~5% | 领域漏斗 → 流水线 → 优化目标式 (1) → 开放问题 |
| 1.1 相关工作 | ~7% | 对比表 + 按轴组织的段落 + 桥接段 + "Our work" |
| 1.2 贡献 | ~4% | 引导句 + 3–4 条 |
| 1.3 技术概览 | ~12–15% | 回顾前人路线 → 归结为若干问题 → Insight 逐一回答 → 一张图 |
| 2 预备知识 | ~12–18% | 精简记号表 + 后文会用到的背景 |
| 3–5 主构造 | ~35% | 定理 → 构造 → 代价/选择规则 → 算法 |
| 6 安全/正确性 | 视类型 | 安全声明、攻击清单、噪声/失败率 |
| 7 实现与评测 | ~12–15% | 基线、平台、参数、配置、结果、消融、对比 |
| 8 结论 | ≤ 半页 | 两到三句 |
| 附录 | 不限 | 证明、扩展表格、复现细节 |

变体：对称密码设计（ToSC/FSE）中安全分析通常是最大的一节，"设计理由"单独成节且比规格本身长；密码分析论文把目标算法的规格放在 §1；安全顶会为双栏格式，威胁模型要早出现；TCC 类理论论文没有实验节。

版式纪律：合法的省页手段依次为收紧浮动体字号与行距、适度减小浮动体与公式间距、缩放 TikZ、删重复脚注 URL，最后才删句子。**禁止**改页边距（geometry）、字号、行距。浮动体前的负 `\vspace` 可能在 PDF 中造成叠印，编辑器预览看不出来，须用脚本扫描。

写之前冻结记号与框架名：一个概念一个符号；框架名在标题、节标题、图注、贡献、概览中完全一致；写完全局 grep 旧符号；附录引用正文编号，不重新编号；概览中的公式从正文复制。

全局风格：尽量不用破折号作句读，改用逗号、冒号或拆句；不用 "Why X is needed / Where the cost goes" 这类解释性小标题；记号表要紧凑并限制在 Notation 小节内；前几页必须让一般密码学读者独立看懂贡献。

## 各节要点

**标题**：点出结构性机制而非参数；两行以内；只有正文确实证明了能特化到每个前人工作的结论时才用 "unified / framework"；避免 novel、efficient、towards；"and Beyond" 类后缀须有真实的推广小节支撑。给出 5–8 个候选并附审稿风险，由作者选择。

**摘要（三段式）**：
- 第一段：领域共识 → 瓶颈 → 已有路线（按路线而非时间分组，每条 1–2 篇代表作并注明会议与年份）→ 以 "However, ... has remained open." 收尾的开放问题。
- 第二段：一句话说清框架的"视角"，然后每条贡献一句（结构 → 上界/刻画 → 新构造 → 算法 → 代价公式）；若声称统一前人工作，必须有"前人方法是本框架的某些特例"这句话。
- 第三段：先给口径（多少实例、什么安全级别），再给区间，再给读者熟悉的具体点，最后是制品/形式化声明（只说真正被形式化的部分）。
- 禁忌：rigorous guarantee、无证明的 optimal、与表格不符的口径、只在附录定义的符号、把复合收益记到单一组件、对过时基线的倍数。另备一份纯文本摘要用于投稿表单，不要从 PDF 复制。

**引言**：领域一句 → 方案选择一句 → 为何需要昂贵组件 → 谱系一句（一次性引用整条工作线）→ 瓶颈（最好有可引用的测量）→ 流水线（每个阶段一个要点、一个映射、一个代价）→ 聚焦句 → **带编号的优化目标式 (1)** → 开放问题。目标式成为全文锚点。论证"现有方案不足"有三档强度：弱（"慢"，不单独用）、中（"在 A 指标上好但在 B 指标上有隐性代价"，用于相关工作）、强（"在它们没有考虑的维度上次优"，用于引言与概览）。若改动看起来像调参，要预先写一句"这不是参数调整"的防御句。

**贡献**：引导句 + 3–4 条，顺序固定为 结构 → 框架 → 算法 → 数字。贡献中不引用引理/定理编号，只指向表格和图；不在贡献中让步或比较（局限放概览或实验的 Remark）；数字只出现在第 1 条（覆盖率）和第 4 条（倍数）；动词力度 prove/establish > identify > introduce > give > implement，避免 study/investigate/explore。"前人各在框架何处"这句话在贡献、相关工作桥接段、概览图注三处口径一致。递进型贡献可用"粗体小标题段落"格式；密码分析论文可用"一个核心发现，其余结果皆由此派生"的叙事。

**技术概览**：让审稿人不读正文也能复述核心思想并相信主定理。结构：回顾记号 → 按论文逐一回顾前人路线（数学层面，给公式与代价，并以事实句指出其遗留问题）→ "两条路线能否结合归结为两个问题 (i)(ii)" → 路标句 → 一张图（前人是角点，本文是新区域）→ Insight 1、Insight 2（**粗体标题本身是完整陈述句**，如 "X bounds Y."）→ 组合恒等式（与正文逐字一致）→ 可选的推广段（只用公式量化，投入产出比最高）。用 "Suppose ..." 引入假设以免循环论证；渐进/密度类结论说"渐进密度，逐实例验证"。

**相关工作**：按"轴"而非时间组织；对比表每行一个工作，最后一行 "Ours"，表注定义全部符号，脚标标注适用范围；段落依次为：引导段、经典工作（每篇一句，末句点出共同局限）、近期两条路线（用一对反义动词并列，如"限制在哪里求值 / 限制如何求值"）、桥接段、"Our work"（五句电梯陈述）、互补方法、同期工作。只用事实性限制评价他人，不用 unfortunately / fail / naive；每个代价公式都对照原文核实；自己的前作用第三人称并像他人一样指出局限；转述前作瓶颈时回去读前作自己的实验节。

**预备知识**：只放后文会用到的内容；记号表只列至少用两次的符号，明确声明与通行记法的不同；新读者友好（每小节一段直觉）。

**主构造**：开场段 → 定义 → 定理（**所有假设显式写出**）→ 证明或证明草图 → 算法（名称 — 一句话功能；带类型的输入输出；行内注释）→ 代价命题（全文统一的"代价货币"）→ 选择规则 → 可用脚本重算的小例子 → 边界 Remark。经验：用自己的参数表逐一检验每个定理的假设；不要把充分条件当必要条件；每个"显然"都交给 falsifier 在小参数上穷举找反例；设计选择要附穷举/搜索证据；以"参数化族 + 推荐实例"呈现以防"只是调参"的指责。

**安全与正确性**：性能类论文写明估计工具与版本、所跑攻击、起约束作用的攻击、分布；每个实例都有安全列；与基线同安全级别；检查近一年针对所用密钥分布的新攻击，若同样影响基线则并排实测并给出对双方都适用的修复；尽量把安全分析外包给标准工具。已知弱点用四层预防性辩护：承认 → 转移 → 量化 → 挂靠已有理论 → 明码标价的退路。对称设计论文：独立的 Security claim 段、从通用到专用的攻击清单、每类攻击落到是否超过声明上限、汇总表；修改已有设计时逐项证明未削弱安全。新假设论文：给出 2–3 个等价形式、搜索到判定等归约、所考虑攻击清单，并声明值得进一步密码分析。

**实验（九段式）**：开场（只改了哪一步，其余与基线相同，所以收益全部来自本方法）→ 基线 → 平台（库与版本、CPU、线程、重复次数与统计量、正确性验证）→ 参数表（含安全列，说明排除项）→ 参数推导 → 配置 → 结果（加速、"组件必须组合且单独都不够"的消融、覆盖与开销）→ 与已发表实现的对比（实测与声称并列，不可比的行标符号并写 "—"）→ 局限 Remark。数字纪律：单一数据源；区间前先给口径；显式声明排除项；复现值与声称值都报；不可比不硬比；收益归因准确；披露开销；消融放正文；保留实测倍数，归一化结果放附录；对基线有利或不利的配置细节要披露。

**结论**：两到三句，不增加新信息，数字与口径同摘要；可加一个开放问题或邀请第三方分析。

**附录**：源文件顶部注明"附录为补充材料，不承重"；每节开头说明支撑正文哪些结论；证明按正文定理顺序；附录表格与正文表格共用数据；正文中"见附录"须精确到小节标签。会议版与全版共用一份源文件，用开关控制；若会议版引用全版，全版必须在 camera-ready 截止前发布。

## 配套流程

- 模拟审稿（`skills/mock-review`）：投稿前 3 天与前 1 天各一轮；先写可证伪清单，派"专家怀疑者 / 通才 / 实现者"（可加数据审计、桌拒审计）优先推翻；主 agent 逐条核实，只接受能在源码、数据或脚本中定位的发现；输出评分与"必改 / 建议 / 不改"修改清单，并列出已核对无误的部分。
- 答辩（`skills/rebuttal`）：拆分原子问题 → 分类（必答 / 澄清 / 认错并修 / 承诺 / 忽略）→ 先写内部详版再压缩为提交版（常见目标 500–700 词）→ 答案先行、证据其次、改动第三 → 把质疑转化为论文新内容 → 主动撤回站不住的数字。
- 匿名检查（`skills/anonymize-check`）：`anon_check.py` 扫描源码、PDF（文本、元数据、嵌入路径、压缩对象流）、补充材料与制品。
- 定稿（`skills/camera-ready`）：页数计数口径、版权表单、作者变更政策、全版发布、0 个未定义引用、字体全部嵌入、无明显 overfull、无叠印。
